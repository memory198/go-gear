# go-gear 架构文档

> 本文讲解 go-gear 的**总体架构**与**模块间协作**；各模块的详细设计见 [模块文档导航](#四模块详解文档导航)。
> 使用层面请参考 [使用指南](使用指南.md)；各方案开发记录见 [方案概览](dev/方案概览.md)。

## 一、总体定位

go-gear 是一个 **Go Web 服务工具集**，由 6 个可独立或组合使用的包构成：配置、带堆栈错误、泛型 HTTP Handler、结构化日志、请求上下文、中间件。它**不绑定路由库**（推荐搭配 chi），**不强制接入 OTel**，每个包都可以单独拿出来用。

## 二、架构总览

```
┌──────────────────────────────────────────────────────────────┐
│                      业务代码（你的 service / handler）        │
└──────────────────────────────┬───────────────────────────────┘
                               │
        ┌──────────────────────▼──────────────────────┐
        │              framework (HTTP 胶水层)          │
        │  Handler[Req,Res] / Handle / HandleContext   │
        │  Bind → Validate → 业务 → WriteOK/WriteError │
        │  Context = gctx.Context（别名再导出）         │
        └───────┬──────────────────────────┬───────────┘
                │                          │
   ┌────────────▼───────┐      ┌───────────▼──────────────┐
   │  middleware (可选)  │      │        gctx              │
   │  Logger / Recoverer │      │ 请求上下文：trace/span   │
   │  OTel               │      │ 超时/取消/值存储          │
   └────────────┬────────┘      └───────────┬──────────────┘
                │                           │ 引用 key 契约
   ┌────────────▼────────┐      ┌───────────▼──────────────┐
   │     logger          │◄─────│   定义 Root/Middle/       │
   │ 默认实例/双编码/滚动 │       │   Current 三个 trace key  │
   └─────────────────────┘      └──────────────────────────┘

   errors（带堆栈错误）    ← 纯工具，谁都不依赖，业务代码直接替换标准库
   config（配置管理）      ← 独立包，只依赖 yaml/fsnotify
```

### 依赖关系一览

| 包 | 依赖（项目内） | 依赖（第三方） | 可独立使用 |
|---|---|---|---|
| `errors` | 无 | 无 | ✅ |
| `config` | 无 | yaml.v3、fsnotify | ✅ |
| `logger` | 无（只定义 trace key 契约） | 无 | ✅ |
| `gctx` | logger（仅引用 3 个 key 常量） | 无 | ✅（需编译 logger） |
| `framework` | gctx | go-playground/validator | ✅ |
| `framework/middleware` | framework、logger | otel SDK | ✅ |
| 业务代码 | 以上任意 | — | — |

## 五、跨模块协作：trace 链路如何贯通

这是全库最关键的协作设计，核心是 **"logger 只读、数据方动态提供"的 key 契约**：

```
logger 定义契约（只读）                     数据提供方（按场景二选一）
┌────────────────────────┐        ┌─────────────────────────────────┐
│ RootTraceIDKey         │◄───────│ gctx.Context.Value()：            │
│ MiddleSpanIDsKey       │        │   动态返回自身 traceID/spanID，   │
│ CurrentSpanIDKey       │        │   middleSpanIDs 从 parent 链聚合  │
│                        │        ├─────────────────────────────────┤
│ traceFromCtx(ctx) 读取 │◄───────│ middleware.OTel：                │
│                        │        │   WithRootTraceID /              │
└────────────────────────┘        │   WithCurrentSpanID 注入 context │
                                  └─────────────────────────────────┘
```

- **不接 OTel**：用 `framework.HandleContext`，业务拿到 `*gctx.Context`，logger 读 key 时由 gctx 动态提供（含中间 span 链）
- **接 OTel**：`middleware.OTel` 在 context 中注入 OTel 的 ID，logger 直接读取；此时建议用 `Handle`（标准 context），避免与 gctx 自生成 ID 冲突

> ⚠️ 两套 ID 来源并存：上游无 `traceparent` 时，gctx 与 OTel 各自生成 ID 可能不一致。**用法约定：接 OTel 的入口用 `Handle`；不接 OTel 用 `HandleContext`**（详见 [dev/2026-09-02-日志链路打通方案](dev/2026-09-02-日志链路打通方案.md) 遗留问题）。

## 六、跨模块协作：一次请求的生命周期

```
HTTP 请求
  │
  ├─[可选] middleware.Logger / Recoverer / OTel     ← 外层横切
  │
  ▼
Handle / HandleContext 包装的 http.HandlerFunc
  ① gctx.NewContext（仅 HandleContext）→ 解析 traceparent / 生成 trace+span ID
  ② Bind()      —— Binder 自定义 or JSON body 解析        （framework/bind.go）
  ③ validator   —— 按 json tag 校验 Req                   （framework/handler.go）
  ④ 业务 handler → 返回 (*Res, error)                     （你的代码）
  ⑤ err==nil ? WriteOK(res) : WriteError(err)             （framework/response.go）
        └─ BizError：{业务码 code, HTTP 状态码, message}
        └─ 其他错误：500 + 统一"服务器内部错误"
  ▼
JSON 响应 {code, message, data}
```

## 七、设计原则

1. **小包独立**：errors/config/logger 无项目内依赖，可单独抽取使用；模块间依赖最弱化（gctx→logger 仅 key 常量）
2. **不重复造轮子**：不做路由（推荐 chi）、不强制 OTel、错误与标准库兼容
3. **context 作为唯一通道**：日志链路字段通过 context + key 契约传递，包间不 import 对方实现
4. **简洁优先**：不提供 kv 字段日志、不提供中间件链，用到再加
5. **失败要显式**：config 重复 key panic、gctx 重复 Set panic，宁可启动失败不静默覆盖

## 八、目录结构

```
├── errors/     # 带堆栈错误：error.go(核心) stack.go(帧捕获) api.go(公开API)
├── config/     # 配置：config.go(加载) hotreload.go(Watcher) value.go(类型安全)
├── logger/     # 日志：logger.go(核心) default.go(默认实例) encoder.go(text/json)
│               #       format.go(entry) level.go trace.go(context key) writer.go(滚动/清理)
├── gctx/       # 请求上下文：ctx.go
├── framework/  # HTTP 胶水：handler.go bind.go response.go error.go context.go(别名)
│   └── middleware/  # logger.go recover.go otel.go
└── docs/       # 使用指南 架构设计(本文) OTel接入指南 模块/(分模块详解) dev/(开发记录)
```
