# 日志 OTLP 导出方案

创建日期：2026-09-22（周二）

## 目标

为 logger 增加**可选的 OTLP 日志导出**能力：把结构化日志记录（含 `trace_id` / `span_id`）通过 OTLP 协议发送到 OTel Collector，与既有 span 链路在同一后端关联（日志 ↔ trace 互跳）。

约束：
- **logger 主包零 OTel 依赖**（与 `middleware/otel.go` 同策略）
- 落盘输出（stdout/file）完全不变，OTLP 为旁路
- 默认不引入任何开销（未挂载时热路径零成本）
- 导出失败不影响业务（异步批量、失败容错）

## 背景

### 为什么需要

当前链路数据分两路：

| 数据 | 通道 | 现状 |
|---|---|---|
| span（链路骨架：耗时/拓扑） | `middleware.OTel` → OTLP | ✅ 已实现 |
| 日志（事件内容 + `trace_id` 关联键） | 仅落盘（stdout/file） | ❌ 无 OTLP 通道 |

缺口：日志与 span 不在同一后端，无法"点开慢 span 直接看到它的日志"；若要用日志替代，则需在采集端（Promtail/Collector filelog）配置解析规则。

### 决策记录

| 路线 | 适用 | 结论 |
|------|------|------|
| 落盘 + 采集器解析（Loki/ELK） | 以排障为主、已有日志采集 | 保留为默认方式，不强制 OTLP |
| 日志 OTLP 导出（本方案） | 已在 OTel 生态、希望 trace ↔ log 原生互跳、免采集解析配置 | **本方案实现**，作为可选功能 |

也可直接用日志做链路近似分析（按 `trace_id` 聚合 + 时间线），但**精确耗时分解与服务拓扑仍依赖 span**：日志只有"点位"（无起止区间）、缺无日志的环节、无显式父子关系，补齐等于手工造 span。

## 方案设计

### 1. 包结构拆分

```
logger/core          数据契约：Level、Record、Attr、Resource（仅标准库）
    ↑        ↑
logger          logger/otlpsink
(门面：Logger、Config、           (可选：OTLP 导出，
 编码器、文件滚动、AddHook)         依赖 core + otel sdk)
```

依赖方向：`otlpsink → core ← logger`。**logger 不 import otel，otlpsink 不 import logger**。

**拆分范围**（务实原则）：

| 内部模块 | 是否拆出 | 理由 |
|---|---|---|
| Level / Record / Attr / Resource | ✅ 拆到 `core` | 多包共享的契约，拆出才有解耦价值 |
| text/json 编码器 | ❌ 留在 logger | 与 Logger 的 `enc` 字段/`encoder` 接口强绑定 |
| 文件滚动/清理 | ❌ 留在 logger | `rotateFile` 直接操作 Logger 状态（file/writers/currentDay），拆出需搬状态或加接口 |
| buffer pool | ❌ 留在 logger | 编码器专用 |

### 2. 数据契约（`logger/core`）

```go
type Level int          // DEBUG/INFO/WARN/ERROR/FATAL

type Record struct {
    Timestamp     time.Time
    Level         Level
    Body          string
    CodeFilepath  string
    CodeLineno    int
    TraceID       string
    SpanID        string
    ParentSpanIDs []string
    Resource      Resource
    Attrs         []Attr
}

type Attr struct{ Key string; Value any }

type Resource struct {
    ServiceName, ServiceVersion, Environment, HostName string
}

// Hook 结构化日志消费点（在 JSON 序列化之前调用）
type Hook func(ctx context.Context, r *Record)
```

### 3. 结构化旁路（序列化前分流）

```go
func (l *Logger) log(ctx, level, msg, args...) {
    rec := &core.Record{...}          // ① 结构化数据成型

    for _, h := range l.hooks {        // ② 序列化前分流（未注册时零开销）
        h(ctx, rec)
    }

    buf := l.enc.appendTo(..., rec)    // ③ 原字节路径不变（stdout/file）
    ...writers...
}
```

要点：**传给 Hook 的是结构化 Record，不是 JSON 字节**——类型保真（数字仍是数字、时间仍是 `time.Time`），无需"sink 再解析 JSON"。

Hook 以 `atomic.Pointer[[]Hook]` 存储，热路径仅一次 nil 判断。

### 4. OTLP sink（`logger/otlpsink`）

```go
sink, shutdown, err := otlpsink.New(ctx,
    otlpsink.WithEndpoint("localhost:4318"),
    otlpsink.WithInsecure(),
    otlpsink.WithService("user-api", "1.2.0"),
)
if err == nil {
    defer shutdown(ctx)        // 必须：刷新 BatchProcessor 缓冲
    l.AddHook(sink.Emit)
}
```

内部组件链：

```
Sink.Emit(ctx, rec)
  → 构造 sdklog.Record（SetTimestamp/SetSeverity/SetBody/AddAttributes）
  → 填 trace/span（双来源，见下）
  → sdklog.Logger.Emit
      → BatchProcessor（批量/定时 flush）
      → otlploghttp.Exporter（OTLP/HTTP protobuf）
      → OTel Collector → Loki/Tempo/...
```

关键实现点：

| 点 | 做法 |
|---|---|
| **severity 映射** | `Level` → `sdklog.SeverityDebug/Info/Warn/Error/Fatal` |
| **trace 关联（双来源）** | 优先 `trace.SpanContextFromContext(ctx)`；无效时回退 `Record.TraceID/SpanID`（gctx 来源，hex 解析） |
| **resource** | `sdklog.WithResource`（service.name/version/deployment.environment/host.name），由 `WithService` 等选项或调用方提供 |
| **协议** | OTLP/HTTP + protobuf（`otlploghttp`），端口 4318，依赖较 gRPC 轻 |
| **关闭** | `shutdown` 调 `LoggerProvider.Shutdown` 刷新缓冲 |
| **失败容错** | BatchProcessor 异步重试后丢弃；不阻塞业务 |

### 5. API 兼容策略

拆分后通过**类型别名 + 常量转发**保持现有用法不变：

```go
// logger 包
type Level = core.Level
type Record = core.Record
type Hook = core.Hook
const (
    DEBUG = core.DEBUG
    ...
)
```

现有 `logger.Config{Level: logger.DEBUG}`、`logger.INFO` 等全部可用。

## 使用形态

```go
l, _ := logger.New(logger.Config{
    Format: logger.JSONFormat, Console: true,
    Service: "user-api", Version: "1.2.0", Env: "prod",
})

sink, shutdown, err := otlpsink.New(ctx,
    otlpsink.WithEndpoint("localhost:4318"),
    otlpsink.WithInsecure(),
    otlpsink.WithService("user-api", "1.2.0"), // 与 logger resource 保持一致
)
if err == nil {
    defer shutdown(ctx)
    l.AddHook(sink.Emit)
}
logger.SetDefault(l)

// 业务代码零改动
logger.Info(ctx, "user created", "user_id", 123)
```

## 依赖增量

| 模块 | 用途 |
|---|---|
| `go.opentelemetry.io/otel/sdk/log` | LoggerProvider / BatchProcessor |
| `go.opentelemetry.io/otel/exporters/otlp/otlplog/otlploghttp` | OTLP/HTTP 导出 |
| `go.opentelemetry.io/otel/sdk`（resource） | resource 构建 |

> 现有 `go.mod` 已含 `otel` + `otel/trace`（middleware 使用）。新增依赖仅由 `logger/otlpsink` 引入；主包不受影响。

| 事项 | 选项 | 倾向 |
|------|------|------|
| Hook 形式 | 函数式 `core.Hook`（`l.AddHook(sink.Emit)`） vs 接口 `core.Emitter` | 函数式（概念更少） |

| 采样 | 是否增加"未采样 trace 丢弃日志" | 默认不加（避免丢日志），后续可选 |
