# logger 包问题清单与修复方案

创建日期：2026-09-22（周二）

## 目标

系统梳理 `logger`（含 `logger/core`、`logger/otlpsink`）现存问题，形成可执行的修复清单并按优先级推进。重点排查**日志静默丢失/误删**类隐患，以及 API 契约与可维护性问题。

## 背景

在完成「日志结构 OTel 对齐 + 手写编码器」与「日志 OTLP 导出」两个方案后做的一轮完整代码审查。核心功能与性能已达标（text 206ns / JSON 388ns），本轮关注正确性与长期可维护性，**不以追求极致性能为目标**。

## 问题清单

### P0 正确性 / 健壮性（建议尽快修）

#### 1. `cleanExpiredLogs` 前缀匹配会误删其他实例的日志

```go
// writer.go
prefix := l.logFilePrefix()               // 例如 Filename = "app"
if !strings.HasPrefix(name, prefix) || !strings.HasSuffix(name, ".log") {
    continue                              // "app2.2026-01-01.log" 也命中 "app" 前缀
}
```

- **影响**：多 Logger 共用一个目录且文件名前缀存在包含关系（`app` / `app2`）时，过期清理可能**删除其他实例的文件**（数据丢失）
- 且不校验日期段格式，`app-debug.*.log` 之类同样会被误删
- **建议**：按 `prefix + "." + YYYY-MM-DD + ".log"` 精确匹配（或解析日期段校验后再删）

#### 2. `rotateFile` 失败后静默丢日志

```go
// writer.go
_ = l.file.Close()                        // 旧文件已关闭
f, err := os.OpenFile(path, ...)
if err != nil {
    fmt.Fprintf(os.Stderr, "logger: rotate failed: %v\n", err)
    return                                // l.file 仍指向已关闭文件，writers 未替换
}
```

- **影响**：跨天滚动失败后（磁盘满/权限问题），后续 `w.Write` 全部失败且被忽略 → **当天日志静默丢失**
- **建议**：失败时明确定义降级行为（如回退 stderr 输出）并保持内部状态一致；写入错误至少上报一次

#### 3. `SetDefault(nil)` / `New` 失败会让包级方法 panic

```go
// default.go
func init() { l, _ := New(...); defaultLogger.Store(l) }  // 忽略 error
func SetDefault(l *Logger) { defaultLogger.Store(l) }     // 不拒绝 nil
// getDefault().Info(...) → nil 解引用 panic
```

- **建议**：`SetDefault` 拒绝 nil；`New` 失败时降级为 stderr logger，而非 Store(nil)

#### 4. `Fatal` 路径不刷新 OTLP 缓冲

- `Fatal` 调用 `os.Exit(1)`，而 `otlpsink` 的 `BatchProcessor` 有缓冲 → **Fatal 前后的日志可能未导出即退出**
- **建议**：文档醒目提示（需配合 `shutdown`）；或为 Hook 增加 `Flush` 能力并在 Fatal 前调用

#### 5. `AddHook` 并发会丢注册（TOCTOU）

```go
// logger.go
old := l.hooks.Load()
next = append(next, *old...)
next = append(next, h)
l.hooks.Store(&next)                      // Load→Store 非原子，并发注册互相覆盖
```

- 注释声称"线程安全"，实际并发 AddHook 会丢失注册
- **建议**：加 `sync.Mutex` 或 CAS 重试；或明确文档"仅启动期注册"

### P1 设计 / 契约

| # | 问题 | 建议 |
|---|------|------|
| 6 | `Print(msg, kv...)` 与 `Printf(format, args...)` 的 args 语义不同，误用不报错 | 文档强化，或 `Print` 改名（如 `PrintKV`） |
| 7 | Hook 无 panic 保护：坏 Hook 会击穿业务日志调用 | Hook 调用处 `defer recover()` + stderr |
| 8 | 写错误被完全忽略（磁盘满/句柄失效无任何信号） | 可选 `OnError func(error)` 回调 |
| 9 | text 编码器不转义：body/属性值含 `\n` 会破坏"一行一条" | 转义换行/回车（JSON 已做） |
| 10 | 重复 attr key 未处理：`"a",1,"a",2` → JSON 重复键，消费者行为不一致 | 后者覆盖，或文档明确 |
| 11 | resource 需两处配置（`logger.Config` 与 `otlpsink.WithService`），易漂移 | 提供 `otlpsink.FromConfig(cfg)` |
| 12 | `otlpsink` 默认 `insecure=true`（明文传输） | 安全默认改为 TLS，`WithInsecure` 显式开启 |
| 13 | `NewFromConfig` 7 个位置参数，易传错、难扩展 | 废弃或改结构/选项 |
| 14 | `contextWithTraceIDs` 无条件标 `FlagsSampled`，未采样链路也被标记 | 与真实采样状态对齐或提供选项 |

## 修复优先级建议

```
第一批（正确性）：#1 误删日志、#2 静默丢日志、#3 nil panic、#5 AddHook 并发
第二批（契约）  ：#7 Hook recover、#9 text 转义、#11 resource 复用、#12 insecure 默认、#4 Fatal flush 提示
第三批（整洁）  ：#6、#8、#10、#13~#19
测试补充        ：T3/T4（对应 #1/#2 的回归保护）、T5
```

> 说明：决定**不做**的项（如极致性能优化：时间格式化缓存、Record/Attrs 池化、caller 单帧快路径）不在本清单内——已明确"不为性能牺牲可维护性"。
